## 0. 사전 준비

```bash
BASE_URL="http://<서버주소>:<포트>"      # 실제 값으로 치환
```

응답 확인에 `jq` 를 쓰면 편하다. 없으면 `python -m json.tool` 로 대체한다.

```bash
sudo apt install -y jq        # 없을 경우
```

Windows PowerShell에서 실행한다면 `curl` 대신 `Invoke-RestMethod` 를 쓰거나 Git Bash를 사용한다.

## 1. T-1 정상 경로 — K=2 적용 확인

중구 OD다. 가장 기본이 되는 확인이다.

```bash
curl -s -X POST "$BASE_URL/route/recommend" \
  -H "Content-Type: application/json" \
  -d '{
    "origin":      {"lat": 37.473565, "lon": 126.621778},
    "destination": {"lat": 37.474748, "lon": 126.603258}
  }' | jq '{
    success,
    n_hotspots: (.k2_hotspots // .k3_hotspots | length),
    distance_m,
    is_hard_case,
    n_swaps
  }'
```

**기대 결과**

| 필드 | 값 |
| --- | --- |
| `success` | `true` |
| `n_hotspots` | **2** (3이면 `ALGO_K` 가 반영되지 않은 것) |
| `distance_m` | 3,000~6,000 범위 |

## 2. T-2 군구 판정 작동 확인

T-1을 보낸 직후 서버 로그를 확인한다.

```bash
# K3s 환경
kubectl logs -f deploy/<배포이름> | grep district_judged

# 컨테이너 직접 실행 중이면
docker logs -f <컨테이너이름> 2>&1 | grep district_judged
```

**기대 결과**

```
district_judged=junggu origin=37.473565,126.621778 nearest_km=0.xxx
```

`district_judged` 로그가 아예 안 보이면 S-2 분기가 호출되지 않는 것이다. `district` 파라미터가 어디선가 채워져서 들어오고 있는지 확인한다.

## 3. T-3 군구 필터가 실제로 적용되는지

후보 수가 줄었는지를 본다. 필터 적용 시 20~30곳대, 미적용 시 40곳대가 기대값이다.

후보 수를 응답에 내려주지 않으므로 로그로 확인한다. 로그에 후보 수가 안 찍히면 S-2 로그 줄 옆에 한 줄 추가한다.

```python
logger.info("candidates=%d district=%s", len(subset), district)
```

**기대 결과**: 인천 전체(41곳대)가 아니라 20~30곳대

## 4. T-4 강화군 Buffer 반경 2.5km 특례

강화군은 핫스팟이 드물어 반경 특례가 적용된다. `district` 가 채워져야만 작동하므로, S-2가 제대로 동작하는지 간접 확인하는 용도이기도 하다.

```bash
curl -s -X POST "$BASE_URL/route/recommend" \
  -H "Content-Type: application/json" \
  -d '{
    "origin":      {"lat": 37.706505, "lon": 126.443398},
    "destination": {"lat": 37.732838, "lon": 126.517697}
  }' | jq '{success, n_hotspots: (.k2_hotspots // .k3_hotspots | length), distance_m}'
```

**기대 결과**

| 항목 | 값 |
| --- | --- |
| `success` | `true` |
| 로그 | `district_judged=ganghwa` |
| 후보 수 | 반경 2.5km 적용 (1.5km일 때보다 많아야 한다) |

## 5. T-5 인천 외 좌표 거절 (4km 가드)

서울시청 좌표다. 인천 핫스팟에서 20km 이상 떨어져 있다.

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST "$BASE_URL/route/recommend" \
  -H "Content-Type: application/json" \
  -d '{
    "origin":      {"lat": 37.566500, "lon": 126.978000},
    "destination": {"lat": 37.570000, "lon": 126.982000}
  }'
```

**기대 결과**: `400`

본문도 확인한다.

```bash
curl -s -X POST "$BASE_URL/route/recommend" \
  -H "Content-Type: application/json" \
  -d '{"origin":{"lat":37.5665,"lon":126.9780},"destination":{"lat":37.5700,"lon":126.9820}}' | jq
```

안내 문구가 그대로 내려오는지 본다. 200이 나오면 가드가 적용되지 않은 것이고, 500이 나오면 예외 처리가 잘못된 것이다.

### 경계값 확인 (선택)

임계값 4km 부근이 궁금하면 인천 동쪽 끝 바깥을 찍어본다.

```bash
# 부천 방면 — 인천 경계에서 벗어난 지점
curl -s -o /dev/null -w "%{http_code}\n" -X POST "$BASE_URL/route/recommend" \
  -H "Content-Type: application/json" \
  -d '{"origin":{"lat":37.503000,"lon":126.766000},"destination":{"lat":37.500000,"lon":126.760000}}'
```

이 지점은 인천 경계에 가까워 4km 안쪽일 수 있다. 200이 나와도 정상이며, 로그의 `nearest_km` 값을 보고 임계값이 적절한지 판단한다.

## 6. T-6 구버전 앱 호환 확인 (2단계 배포 직후 필수)

응답에 **두 필드가 모두 있어야** 구버전 앱이 깨지지 않는다.

```bash
curl -s -X POST "$BASE_URL/route/recommend" \
  -H "Content-Type: application/json" \
  -d '{"origin":{"lat":37.473565,"lon":126.621778},"destination":{"lat":37.474748,"lon":126.603258}}' \
  | jq 'has("k3_hotspots"), has("k2_hotspots")'
```

**기대 결과**

| 단계 | `k3_hotspots` | `k2_hotspots` |
| --- | --- | --- |
| 2단계 배포 직후 | `true` | `true` |
| 4단계 완료 후 | `false` | `true` |

2단계에서 `k3_hotspots` 가 `false` 로 나오면 **구버전 앱이 즉시 깨진다.** 롤백 대상이다.

## 7. T-7 `district` 를 명시적으로 보냈을 때

앱은 현재 보내지 않지만, 스키마상 선택 필드로 남아 있으므로 동작을 확인해 둔다.

```bash
# 정상 값
curl -s -X POST "$BASE_URL/route/recommend" \
  -H "Content-Type: application/json" \
  -d '{
    "origin":      {"lat": 37.473565, "lon": 126.621778},
    "destination": {"lat": 37.474748, "lon": 126.603258},
    "district":    "junggu"
  }' | jq '{success, n_hotspots: (.k2_hotspots // .k3_hotspots | length)}'
```

**기대 결과**: 성공. 로그에 `district_judged` 가 **찍히지 않는다** (좌표 판정을 건너뛰므로).

```bash
# 알 수 없는 값 — 2026-07-01 행정개편 후의 구 이름
curl -s -X POST "$BASE_URL/route/recommend" \
  -H "Content-Type: application/json" \
  -d '{
    "origin":      {"lat": 37.473565, "lon": 126.621778},
    "destination": {"lat": 37.474748, "lon": 126.603258},
    "district":    "jemulpo"
  }' | jq '{success, n_hotspots: (.k2_hotspots // .k3_hotspots | length)}'
```

**기대 결과**: 성공. 알 수 없는 값이므로 좌표 판정으로 넘어가 로그에 `district_judged=junggu` 가 찍힌다.

이 동작이 중요한 이유는 문서 3절에 적어두었다. 인천시 행정체제가 2026년 7월 1일 개편되어 중구·동구가 제물포구·영종구로, 서구가 서해구·검단구로 바뀌었다. 핫스팟 데이터는 개편 전 이름을 쓰므로, 앱이 나중에 현재 구 이름을 보내더라도 서버가 무시하고 좌표로 판정해야 한다.

## 8. T-8 회귀 확인 — 9개 군구 일괄

기존 검증 OD 전체를 한 번씩 돌려 500·502가 없는지 본다.

```bash
cat <<'EOF' > /tmp/ploggo_od.txt
ganghwa  37.706505 126.443398 37.732838 126.517697
junggu   37.473565 126.621778 37.474748 126.603258
donggu   37.470733 126.641914 37.487780 126.621754
michuhol 37.455015 126.667435 37.435062 126.690721
seogu    37.545115 126.676062 37.552748 126.650239
yeonsu   37.391182 126.645092 37.418275 126.661122
namdong  37.447245 126.731453 37.447769 126.700089
bupyeong 37.507046 126.721858 37.482179 126.703038
gyeyang  37.537367 126.737744 37.530279 126.722516
EOF

while read -r name olat olon dlat dlon; do
  resp=$(curl -s -w "\n%{http_code}" -X POST "$BASE_URL/route/recommend" \
    -H "Content-Type: application/json" \
    -d "{\"origin\":{\"lat\":$olat,\"lon\":$olon},\"destination\":{\"lat\":$dlat,\"lon\":$dlon}}")
  code=$(echo "$resp" | tail -1)
  body=$(echo "$resp" | head -n -1)
  n=$(echo "$body" | jq -r '(.k2_hotspots // .k3_hotspots // []) | length')
  km=$(echo "$body" | jq -r '.distance_m // 0')
  hard=$(echo "$body" | jq -r '.is_hard_case // "-"')
  printf "%-10s HTTP %s  경유 %s곳  %sm  hard=%s\n" "$name" "$code" "$n" "$km" "$hard"
done < /tmp/ploggo_od.txt
```

**기대 결과**

- 9건 모두 `HTTP 200`
- 경유 핫스팟 전부 **2곳**
- `hard=true` 가 섞여 나오는 것은 정상이다. 공업지대를 완전히 피하지 못한 경우이며, 오류가 아니다

## 10. 실패 시 확인 순서

| 증상 | 먼저 볼 곳 |
| --- | --- |
| 경유가 계속 3곳 | `.env` 의 `ALGO_K` 반영 여부. 컨테이너 재시작 했는지 |
| `district_judged` 로그 없음 | S-2 분기가 `subset` 계산보다 **아래**에 들어가지 않았는지 |
| 후보 수가 여전히 40곳대 | `district` 가 채워졌는데도 `subset` 이 비어 폴백을 타는지. `source_district` 값의 표기(영문/한글) 일치 확인 |
| 인천 외 좌표에 500 | `HTTPException` 이 아닌 일반 예외가 발생. `haversine_vec` 인자 형태(`(lat, lon)` vs `(lon, lat)`) 확인 |
| 모든 요청에 502 | Tmap 프록시 문제. 이번 변경과 무관하므로 기존 경로로 점검 |
